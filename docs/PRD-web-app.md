# Product Requirements Document
## Elite-Data-Intelligence Web Application

**Owner:** Founder, Elite-Data-Intelligence  
**Version:** 1.0  
**Date:** September 2026  
**Status:** Approved for scaffolding

---

## 1. Purpose

I am building the official web application for Elite-Data-Intelligence. It serves three audiences:

1. **Public visitors / prospects** — Marketing site that converts interest into discovery calls.
2. **Clients** — Secure portal for project status, deliverables, validation reports, and support.
3. **Internal team (me + senior core)** — Ops dashboard for pipeline, utilization, credit spend, agent health, and risk.

The site must feel premium, structured, and editorial — matching the Mission responsive landing page reference (bold oversized typography, high-contrast black/white, cinematic scrolling, restrained accent color).

---

## 2. Goals & Success Metrics

| Goal | Metric |
|------|--------|
| Convert prospects | Discovery-call booking rate from website visitors |
| Reduce my support load | % of routine queries handled by Customer Support Agent |
| Give clients transparency | Client portal login rate + status-view frequency |
| Keep me in control | Real-time visibility of pipeline, credits, and risks |
| Brand consistency | Design matches the editorial reference on desktop & mobile |

Target: Support the path to $100k monthly revenue by making the agency look and operate at enterprise level from day one.

---

## 3. User Personas

- **Prospect** — Enterprise decision-maker exploring AI/analytics partners. Needs clarity, credibility, and easy booking.
- **Client** — Existing engagement stakeholder. Needs status, documents, and fast answers without chasing me.
- **Founder / Senior Core** — Me and key humans. Need pipeline health, credit burn, agent status, and risk register at a glance.

---

## 4. Core Modules

### 4.1 Public Marketing Site (Unauthenticated)

**Pages / Sections:**
- **Hero** — Large editorial headline + sub-headline + primary CTA (“Book a Discovery Call”).
- **Mission** — Short statement of what Elite-Data-Intelligence stands for.
- **Approach / Process** — How we work (data → models/agents → production → adoption → value).
- **Impact / Numbers** — Key proof points (to be filled with real metrics later).
- **Selected Work / Case Studies** — Placeholder structure for outcome-focused stories.
- **Team & Agents** — Transparent view of human core + agent system (high-level only).
- **Contact / Start** — Form + live Customer Support Agent chat widget.

**Key Interactions:**
- Smooth cinematic scroll.
- Live chat powered by Customer Support Agent.
- One-click or short-form discovery-call booking that feeds the Project Manager + Engagement Manager.

### 4.2 Client Portal (Authenticated)

**Features:**
- Secure login (email magic link or SSO-ready).
- Dashboard showing active engagements, milestone progress, and latest validation status.
- Deliverables repository (versioned files, model cards, reports).
- Status & validation reports generated by agents.
- Support ticket / chat with Customer Support Agent (context-aware of the client’s projects).
- Simple outcome metrics view (what was promised vs what is measured).

### 4.3 Internal Ops Dashboard (Restricted)

**Features (Founder + designated seniors only):**
- Pipeline & utilization overview.
- AI credit / compute spend vs budget.
- Agent health (timeouts, failure rates, open quality debt).
- Risk register summary.
- Cash collection / outstanding view (high-level).
- Quick links to GitHub project boards and key issues.

---

## 5. Design Requirements

**Visual System (locked to reference):**
- Bold, oversized editorial typography.
- High-contrast black / white base.
- One accent color used sparingly (yellow or refined equivalent — final choice during implementation).
- Clean grid, generous whitespace, strong hierarchy.
- Cinematic but restrained motion (scroll-triggered reveals, no clutter).
- Fully responsive (desktop first, excellent mobile).

**Tone of Voice on Site:**
Premium, confident, concise, outcome-oriented. No hype language. No mention of internal agent costs or limitations.

---

## 6. Technical Requirements

**Stack (approved):**
- Next.js (App Router) + TypeScript
- Tailwind CSS + custom design tokens for the editorial system
- Authentication: Clerk or Auth.js (magic link + future SSO)
- Database: Postgres (via Supabase, Neon, or Vercel Postgres) for portal data, bookings, tickets
- Hosting: Vercel
- Chat / Agent interface: API route that will later connect to the Customer Support Agent
- GitHub webhooks (later) for live status pulls

**Non-Functional:**
- Performance: Lighthouse 90+ on key pages
- Accessibility: WCAG 2.1 AA baseline
- Security: No public exposure of client data; proper role-based access
- SEO: Clean metadata, Open Graph, structured data for the marketing pages

---

## 7. Customer Support Agent Integration

- Chat widget on public site and inside client portal.
- Booking flow writes to a structured store that notifies Project Manager + Engagement Manager.
- Authenticated clients receive context-aware status and document links.
- All conversations logged for audit and improvement by the Failure Analysis Agent.

---

## 8. Out of Scope for MVP

- Full CRM replacement
- Automated invoicing / payments (manual or Stripe later)
- Real-time production monitoring of client models (Phase 2)
- Multi-language
- Advanced analytics inside the ops dashboard (basic first)

---

## 9. MVP Delivery Order

1. Design tokens + layout shell + marketing pages (Hero → Contact)
2. Basic booking form + Customer Support chat placeholder
3. Auth + Client Portal shell + project status view
4. Internal Ops Dashboard shell
5. Connect real agent endpoints and GitHub data (iterative)

---

## 10. Acceptance Criteria for Scaffolding

- Next.js project initialized inside `/web-app`
- App Router structure with route groups for (marketing), (portal), (ops)
- Tailwind configured with custom editorial design tokens
- Placeholder pages for all core sections
- README inside `/web-app` explaining how to run and the PRD link
- Design tokens documented so future UI matches the Mission reference
